# Roadmap

Each milestone ends with `make check` (gofmt, `go vet`, `go test -race`) passing and its documentation updated.

`sdd` runs inside the coding agent the user already has (see [BRIEF.md](BRIEF.md)): it never calls an LLM itself. M2 was built before that decision and is parked for a possible API mode.

| Milestone | Scope | Exit criteria |
|---|---|---|
| **M0: Scaffold** ✅ | Go module, CLI dispatcher, embedded templates and profiles, `sdd init`, `sdd version`, state, journal and lock packages | `sdd init` creates the project layout in an empty repo; unit tests pass |
| **M1: Specs, plans and state** ✅ | Spec and plan parsers, deterministic lint, workflow state machine wired to commands, `sdd status`, `sdd spec new/lint/approve`, `sdd plan new/approve`, staleness detection, `sync check` (spec↔spec, spec↔plan), `trace` over specs and plan, feature names and `sdd feature describe` | A spec written by hand can be linted, approved and traced; editing it marks downstream artifacts stale |
| **M2: Claude provider** ⏸ parked | Anthropic Messages API over `net/http`, SSE streaming, tool use, retries and backoff, usage accounting, redacted transcripts | Done and tested; unused until an API mode is scheduled |
| **M3: Agent integration + Specify** ✅ | `sdd mcp` (official MCP Go SDK, stdio) with `status`, `guide`, `spec_new`, `plan_new`, `lint`, `sync_check`, `trace`; `sdd guide`; `sdd init --agent claude` (`.mcp.json`, `/sdd-*` commands, permission rules) and `--agent generic` (`AGENTS.md`), creating only missing files; `sdd init --check`; ephemeral paths in `.sdd/.gitignore`; agent actor in the journal | In Claude Code, a functional and a technical spec are drafted with the agent through `/sdd-spec` and `/sdd-tech`, linted through MCP and approved by the user; the agent cannot approve |
| **M4: Plan** ✅ | `/sdd-plan`, the plan guide (format, limits, approved specs) and validation through MCP | A plan drafted by the agent passes validation, covers every FR and AC, and is approved by the user |
| **M5: Implement** ✅ | Git worktrees, `sdd implement`, `task_next` / `task_done` / `group_verify` (MCP and CLI), verification with the technical spec's commands, WIP checkpoints squashed into group commits with trailers, changes outside declared files reported, fix-attempt limit, `review`, `approve`, `revise`, `resume`, `clean`, `/sdd-implement` | A sample feature is implemented group by group from Claude Code; ending the agent session mid-task and starting a new one continues from the right task |
| **M6: Validate** ✅ | `sdd validate`, plan↔code sync, full `trace` including commits and tests, `report.md`, `review_context` and `/sdd-deep-review` | `sdd validate` produces a passing report for the sample feature |
| **M7: Brownfield adoption** ✅ | `sdd adopt --context` / `adopt_context` (languages, build files, detected commands, layout, tests, docs), baseline features (`sdd spec new --baseline`, `origin: existing`, `baselined` phase), `/sdd-adopt`, baseline-aware sync and trace, revising a baseline when a later feature changes adopted behavior | An existing sample project is adopted into baseline specs without changing its code, and a new feature that depends on the baseline goes through all four phases |
| **M8: More agents** | Integration files for Codex CLI and Gemini CLI (MCP registration, commands or prompts, permission guidance) on top of the shared MCP server and `AGENTS.md` | The same sample feature runs end to end in each supported agent |
| **Later** | API mode for unattended runs (an agent loop inside `sdd` on the M2 provider, plus Gemini and OpenAI adapters), more language profiles, `sdd upgrade` migrations, parallel features | — |

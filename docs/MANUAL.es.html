Quipu

Construye a partir de la spec con sdd

Un quipu es el registro inca de cuerdas anudadas, donde cada nudo es un dato atado a los demás. Quipu ata cada requisito a su diseño, sus tareas, sus commits y sus pruebas. Tu agente de código escribe las specs, el plan y el código. Tú apruebas cada paso. sdd lo verifica todo, hace los commits y deja registro de quién hizo qué.

Qué es

Un binario, cuatro fases, sin sorpresas

Quipu es una herramienta de línea de comandos, sdd, que funciona junto al agente de código que ya usas. Todo cambio en tu proyecto empieza como una feature: una spec escrita de lo que debe hacer, un diseño técnico, un plan dividido en tareas pequeñas y, solo después, el código. Cada fase termina en una puerta que solo una persona puede abrir.

Usa tu suscripción

El razonamiento lo pone Claude Code, con tu propio plan. sdd es determinista y funciona sin conexión.

Las personas aprueban

El agente no puede aprobar. Sus reglas de permisos y un hook se lo impiden, incluso dentro de envoltorios como bash -c, y sdd rechaza las aprobaciones que vienen del agente. Tú apruebas en tu terminal (sdd approve G1), o con ! sdd approve G1 dentro de Claude Code.

Todo es trazable

Requisito → diseño → tarea → commit → prueba. sdd trace FR-001 muestra la cadena completa.

El flujo

Cuatro estaciones, con una puerta en cada una

Una feature avanza de izquierda a derecha. El agente redacta lo que hay en cada estación; las puertas en ámbar son tuyas. Si un documento aprobado cambia después, sdd marca como desactualizado todo lo que depende de él.

1

Especificar

Qué debe hacer la feature y, después, cómo se va a construir.

functional.md FR · NFR · AC
technical.md ADR · comandos
Tu puerta ×2sdd spec approve <f> --functionalsdd spec approve <f> --technical
2

Planear

Grupos de tareas pequeñas. Todos los requisitos deben quedar cubiertos.

plan.md G1 · T1.1 …
Tu puertasdd plan approve <f>
3

Implementar

El agente programa una tarea a la vez en un worktree de git aislado. Cada grupo termina en un commit.

rama sdd/<f> 1 commit / grupo
Tu puerta, por gruposdd review G1sdd approve G1
4

Validar

Pruebas de integración, todas las verificaciones de consistencia y un reporte final.

report.md fase: validated
Lo ejecutas túsdd validate <f>
en cualquier momentosdd statussdd sync checksdd trace <ID>muestran dónde estás, qué está desactualizado y cómo se conecta un ID.
Instalación · una vez

Instala, inicializa, conecta

Necesitas Go 1.25, git y un agente de código: Claude Code, Codex CLI o Antigravity CLI. Elige el tuyo y el manual adapta sus comandos. El binario se instala una vez por máquina; cada proyecto se prepara con sdd init, que solo crea los archivos que faltan y nunca modifica uno que ya tengas.

A · por máquina

Instala sdd

$ go install github.com/darkcarard/quipu-sdd/cmd/sdd@latest
$ sdd version

Se instala en ~/go/bin. Asegúrate de que esa carpeta esté en tu PATH. También puedes clonar el repositorio y ejecutar make install.

B · por proyecto

Inicializa el proyecto

$ cd mi-proyecto
$ sdd init --agent claude
$ git add -A
$ git commit -m "Set up sdd"

Agrega sdd.yaml, las plantillas y los archivos de tu agente: los skills /sdd-*, el servidor MCP y el hook que reserva las aprobaciones para ti. Para varios agentes, sepáralos con comas (--agent claude,codex). El repositorio necesita al menos un commit antes de implementar.

C · por proyecto

Abre Claude Code

$ claude
# aprueba el servidor MCP "sdd"
> /mcp

Claude Code pide una vez aprobar el servidor sdd. /mcp debe mostrarlo conectado, y al escribir / aparecen los skills /sdd-*. Ejecuta los comandos sdd en una terminal, o con ! dentro de Claude Code.

$ codex
# confía en el proyecto cuando te lo pida
> /mcp
> /hooks

Codex solo lee .codex/ en proyectos de confianza. /mcp muestra el servidor sdd, /hooks te deja revisar y aprobar el hook que reserva las aprobaciones para ti, y al escribir $ aparecen los skills $sdd-*. Ejecuta los comandos sdd en otra terminal.

Configurado según su documentación; aún sin probar de extremo a extremo. Cuéntanos cómo te va.

$ agy
# confía en la carpeta cuando te lo pida
> /mcp

/mcp muestra el servidor sdd, y al escribir / aparecen los skills /sdd-* (ejecuta /skills reload si faltan). Ejecuta los comandos sdd en otra terminal.

Configurado según su documentación; aún sin probar de extremo a extremo. Cuéntanos cómo te va.

Tu primera feature

De una idea a código validado

Ten dos ventanas abiertas: Claude Code, donde trabaja el agente, y una terminal, donde apruebas tú. Reemplaza <f> por el nombre de feature que te da sdd; sdd status las lista.

1

Describe lo que quieres

El agente crea la feature, te hace preguntas y escribe la spec funcional: requisitos (FR-001), requisitos no funcionales (NFR-001) y criterios de aceptación verificables (AC-001). sdd convierte tu descripción en un nombre de feature corto y seguro.

en Claude Code
> /sdd-spec Una CLI de lista de tareas: agregar, listar y completar tareas guardadas en un JSON
en tu terminal
$ sdd status
$ sdd spec lint <f>
$ sdd spec approve <f> --functional
2

Acuerda el diseño

La spec técnica registra la arquitectura, las decisiones (ADR-001), qué componente cubre cada requisito y los comandos de build, lint y pruebas que sdd ejecutará para verificar el código.

en Claude Code
> /sdd-tech <f>
en tu terminal
$ sdd spec approve <f> --technical
Revisa que los comandos de verificación sean reales, por ejemplo go build ./... y go test ./....
3

Aprueba el plan

El plan divide el trabajo en grupos (G1, G2…) de tareas pequeñas (T1.1…), cada una sobre pocos archivos. sdd sync check falla si algún requisito o criterio queda sin cubrir.

en Claude Code
> /sdd-plan <f>
en tu terminal
$ sdd sync check <f>
$ sdd plan approve <f>
4

Implementa, un grupo a la vez

Tú inicias la implementación; sdd crea un worktree aislado en la rama sdd/<f>. El agente avanza por el grupo y se detiene cuando está listo para tu revisión. Apruébalo para continuar o devuélvelo con comentarios.

en tu terminal
$ sdd implement <f>
en Claude Code
> /sdd-implement <f>
en tu terminal, por grupo
$ sdd review G1          # --diff para ver el diff completo
$ sdd approve G1
# o devuélvelo:
$ sdd revise G1 -m "Maneja el caso del archivo vacío"
agentesddtú
task_next→ escribe código→ task_done→ build · lint · pruebas↺ siguiente tarea
group_verify→ un commit con trailers SDD→ sdd review→ approveorevise→ /sdd-implement

Si una verificación falla, el agente recibe la salida del error y lo corrige, hasta limits.max_fix_attempts veces (3 por defecto). Ejecuta /sdd-implement <f> de nuevo después de cada aprobación hasta terminar todos los grupos. Dentro de Claude Code, ejecuta los comandos sdd con un ! delante (! sdd approve G1); /sdd-implement es un comando slash y va sin !.

5

Valida y cierra

sdd ejecuta las pruebas de integración, comprueba que cada grupo tenga su commit y que cada criterio de aceptación tenga una prueba (un comentario covers: AC-001), y escribe el reporte. Si quieres, pide al agente una revisión semántica contra los criterios.

en tu terminal
$ sdd validate <f>
$ sdd trace --matrix <f>
$ sdd merge <f>
en Claude Code · opcional
> /sdd-deep-review <f>
sdd merge integra la rama sdd/<f> en la rama activa de tu proyecto, desde cualquier directorio, elimina el worktree y hace commit de los registros de la feature. ¿Prefieres un pull request? Intégrala a tu manera y luego ejecuta igualmente sdd merge <f>: verá que el trabajo ya está ahí y solo lo registrará.
Proyectos existentes

Adopta el código que ya tienes

En un proyecto que ya tiene código, empieza por documentarlo. sdd adopt arma un inventario corto (lenguajes, archivos de build, comandos probables, pruebas) y el agente escribe a partir de él specs baseline. Tu código no se toca. Las features baseline no tienen plan; el trabajo nuevo empieza como features normales sobre ellas.

en Claude Code
> /sdd-adopt
# o un área a la vez:
> /sdd-adopt billing
en tu terminal
$ sdd spec approve <f> --functional
Dónde queda todo

Todo es un archivo en tu repositorio

Las specs, los planes, el estado y el journal de auditoría se guardan en git junto con tu código, así que el historial viaja con el proyecto: sdd hace commit de specs/<f>/ y .sdd/features/<f>/ en cada aprobación y en sdd merge, y de nada más que tengas en el stage. Los worktrees, locks y logs de ejecución son locales y se ignoran con .sdd/.gitignore.

log.md es una versión legible del journal: cada paso, quién lo ejecutó (tú o agent:claude-code) y cuándo.

mi-proyecto/ ├─ sdd.yaml # límites y ajustes ├─ specs/ │ └─ todo-cli/ │ ├─ functional.md # qué │ ├─ technical.md # cómo │ └─ plan.md # tareas ├─ .sdd/ │ ├─ templates/ profiles/ │ ├─ features/todo-cli/ │ │ ├─ state.json # fase, aprobaciones │ │ ├─ journal.jsonl # auditoría │ │ ├─ log.md │ │ └─ report.md │ └─ worktrees/ # solo local ├─ .mcp.json └─ .claude/ skills/ settings.json
Referencia

Los comandos de un vistazo

Todos los comandos aceptan --help. El agente usa las mismas funciones a través del servidor MCP sdd; los comandos marcados tú nunca están disponibles para él.

ComandoQuiénQué hace
sdd init --agent claudetúPrepara el proyecto para Claude Code (claude, codex, antigravity o generic). --check lista lo que falta.
sdd status [<f>]cualquieraFase de cada feature y la siguiente acción.
/sdd-spec · /sdd-tech · /sdd-planagenteRedactan la spec funcional, la spec técnica y el plan.
sdd spec approve <f> --functional|--technicaltúCongela una spec con su contenido actual y hace commit de los registros de la feature.
sdd plan approve <f>túCongela el plan.
sdd implement <f>túCrea el worktree e inicia el primer grupo.
/sdd-implement <f>agenteAvanza por el grupo actual hasta dejarlo listo para revisión.
sdd review G1 [--diff]túResumen del grupo que espera revisión. Acepta el ID del grupo, una feature, o nada cuando solo una feature se está implementando.
sdd approve G1 · sdd revise G1 -m "…"túAcepta el grupo o lo devuelve con comentarios.
sdd validate <f>túPruebas de integración, todas las verificaciones y report.md.
sdd merge [<f>]túIntegra una feature validada en tu rama, elimina su worktree y hace commit de sus registros.
sdd sync check [<f>]cualquieraConsistencia entre specs, plan y código.
sdd trace <ID> · --matrix <f>cualquieraSigue un ID o imprime la matriz de trazabilidad completa.
sdd feature describe <f>túCambia el título o la descripción de una feature.
/sdd-adopt · /sdd-deep-reviewagenteDocumenta código existente; revisa el código contra los criterios.
sdd resume <f> · sdd clean <f>túRepara tras una interrupción; elimina el worktree (la rama se conserva).
Cuando algo sale mal

Situaciones comunes

No sé en qué punto estoy

Ejecuta sdd status <f>. Muestra la fase, el estado de cada documento y el comando exacto que sigue.

Claude Code se cerró a mitad de una tarea

Ejecuta sdd resume <f> en tu terminal y luego /sdd-implement <f> otra vez. El journal sabe qué paso estaba en curso.

Edité una spec después de aprobarla

La aprobación ya no coincide. sdd sync check muestra qué quedó desactualizado; revisa el cambio y vuelve a aprobar.

El agente dice que no puede aprobar

Es intencional. Ejecuta tú la aprobación en una terminal.

No aparecen las herramientas MCP

Comprueba que which sdd encuentra el binario, reinicia Claude Code en la carpeta del proyecto y aprueba el servidor.

Un grupo sigue fallando sus verificaciones

Cuando se agotan los intentos de corrección, el grupo queda marcado como fallido y el agente se detiene. Revisa sdd status <f> y envía indicaciones con sdd revise G1 -m "…" (el grupo fallido).
